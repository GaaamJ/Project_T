# Sandbox 스테이지

## 역할

실타래 파괴 → 실 버프 획득 → 중앙 반납을 배우는 플레이 공간.

처음 만드는 스테이지였기에, 기믹의 기초가 되는 부분을 설계하고 내가 게임 스테이지를 제대로 만들 수 있는지 판단하고 싶었다. 동시에 게임의 기초적인 시스템이 재미가 있을지 판단하려고 했다.

## 동작

### 시작부터 클리어까지

핵심 흐름은 복잡한 메커니즘 대신 간단한 기믹으로 가고 싶어서 정했다.

1. **시작:** SandBox 씬 실행 → 시작 구역 대기 → 시작 구역 이탈 → 실타래 생성.
2. **탐색과 획득:** 방 탐색 → 실타래 공격 → 실 버프 획득.
3. **반납과 반복:** 좌표에 묶기 → 실타래 재배치 → 탐색 반복.
4. **클리어:** 좌표 6개 활성화 → 스테이지 클리어.

### 탐색 중 동행과 기록

- [[우미아]]가 플레이어와 동행한다.
- 방에 들어가면 [[공간-기록]]에 방문이 저장된다.

### 대기와 시작

- 씬 시작 시 대기(Waiting) 상태로 진입하며, 이 때는 [[실타래]]가 생성되지 않는다.
  - 데스티니에서 시작 구역에 모여 작전을 논의하고 잡담을 나누던 경험을 참고했다. 이 게임에서도 우미아와 작전을 논의하고 잡담을 나눌 수 있는 공간을 만들고 싶어서 시작 전 대기 구역을 두었다.
- 플레이어가 시작 구역(StartZone)을 벗어나면 진행 중(InProgress) 상태로 전환되고 붉은 / 푸른 / 금빛 실타래를 1개씩 생성한다.

### 진행과 재배치

- 플레이어가 실 버프를 좌표에 묶거나 버프 시간이 만료되면 실타래를 재배치한다.
  - 플레이어가 지나치며 “아, 여기에 실타래가 있네? 나 지금 버프 들고 있으니, 이거 반납하고 여기 와서 반납해야지.”라고 계획하는 것을 막고 싶었다. 그래야 우미아가 주는 힌트의 가치가 커질 것이라고 생각해서 실타래를 재배치하도록 정했다.
- 재배치 시 활성화된 [[좌표]]는 유지한다.
  - 이미 활성화한 좌표는 스테이지 클리어의 주요 진척도이므로 재배치해도 유지한다.

### 클리어와 초기화

- [[좌표]] 6개가 모두 활성화되면 클리어(Clear) 상태로 전환되고, 씬의 실타래가 제거되며 추가 생성이 중단된다.
  - 좌표를 모두 활성화하는 클리어 기준은 6개가 딱 적당하다고 생각해서 정했다.
- 클리어 후에는 클리어 상태를 유지하며, 자동으로 대기 상태로 복귀하지 않는다.
- 진행 중 실패하면 좌표 전체 비활성화, 실타래 제거, 버프 초기화 후 대기 상태로 복귀한다. 플레이어는 시작 구역 중앙으로 이동한다.
  - 재시도는 데스티니의 Wipe 후 리트라이를 참고했다. 플레이어가 여러 번 스테이지를 반복하며 숙달되고, 우미아와 무언가 해냈음을 보여 주고 싶었다.

### 문

- 문은 닫힌 상태로 초기화되며 외부 요청으로 열 수 있다.
  - 닫혀 있는 문은 클리어 후 갈 수 있는 곳을 개방하는 역할로 생각했다.

## 규칙

### 공간 구성과 이동

- 중앙 반납 공간과 좌·우·하 방향의 탐색 방 6개로 구성된다.
  - 플레이어가 위에서 내려와 이 스테이지에 입장했다고 생각했다. 전체적으로 데스티니 레이드의 마지막 소원, 금고 맵을 참고했다.
  - 탐색 계층을 추가해 더 깊은 곳으로 가고, 공간을 분리한다는 느낌을 생각했던 것 같지만, 이 부분의 의도는 기억이 확실하지 않다.
- 방 사이 이동 구역에 진입하면 연결된 도착 위치로 이동한다.
  - 방 사이를 연결된 위치로 이동하는 방식은 우선 공간을 분리하기 쉬울 것 같아서 선택했다.
- 시작 구역은 크기 10×5의 트리거 콜라이더로 정의된다.
  - 크기 자체에 특별한 설계 의도는 없다. 현재는 시작 구역이 시각적으로 확실히 구분되어 있지 않다.

### 실패 조건

- 실패 조건(체력, 패리, 맵 패턴)은 미구현이며 외부에서 API로 트리거할 수 있다.
