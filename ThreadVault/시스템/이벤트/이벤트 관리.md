# 이벤트 관리

> [!warning] 초안
> Issue #39의 구현과 검증이 끝난 뒤 실제 동작에 맞게 반영한다. 현재 구현된 동작을 설명하는 문서가 아니다.

## 역할
이 문서에서 이벤트는 대사, 컷씬, 캐릭터 동작처럼 Yarn으로 순서를 제어하는 이야기 진행 단위를 뜻한다.

이벤트 관리 시스템은 각 이벤트의 실행 조건과 완료 상태를 관리한다.

| 구분             | 담당         |
| -------------- | ---------- |
| 이벤트 실행 여부 판단   | 이벤트 관리 시스템 |
| 완료 상태 저장       | 이벤트 관리 시스템 |
| 대사와 연출 순서      | Yarn       |
| 컷씬·대화 UI·음향 출력 | 각 게임 시스템   |

## 실행 흐름
1. 씬이나 상호작용 대상 등이 이벤트 실행을 요청한다.
2. 다음 조건을 확인한다.
   - 선행 이벤트가 완료되었는가
   - 이미 완료된 일회성 이벤트인가
   - 다른 이벤트가 실행 중인가
3. 실행할 수 있다면 지정된 Yarn Node를 시작한다.
4. Yarn이 대사와 연출을 진행한다.
5. Yarn이 끝나면 이벤트의 고유 ID를 완료 목록에 기록한다.

```text
이벤트 요청
→ 실행 조건 확인
→ Yarn Node 실행
→ 대사와 연출 진행
→ 완료 ID 저장
```

## 완료 상태
- 완료된 이벤트는 고유 ID로 구분한다.
- 완료 ID는 게임 저장 데이터에 포함한다.
- 같은 ID는 중복해서 저장하지 않는다.
- 완료된 일회성 이벤트는 다시 실행하지 않는다.
- 한 번에 하나의 이벤트만 실행한다.

## 이벤트 추가
새 이벤트는 다음 과정으로 추가한다.

1. Yarn Node를 작성한다.
2. 이벤트 데이터를 생성한다.
3. 이벤트가 발생할 씬이나 오브젝트에 등록한다.

일반적인 새 이벤트 추가는 위 과정으로 끝난다. 기존 이벤트와 저장 구조에 이벤트별 분기를 추가하지 않는다.

## 확장
기존에 없는 기능이 필요한 경우 재사용 가능한 기능으로 추가한다.

- 새로운 실행 조건
- 새로운 이벤트 발생 방식
- 새로운 Yarn 연출 명령
- 새로운 게임 상태 조회 기능

하나의 이벤트만을 위한 전용 관리자나 저장 필드는 만들지 않는다.

## 규칙
- 모든 이벤트는 서로 겹치지 않는 고유 ID를 가진다.
- 이벤트 ID는 완료 상태를 식별하는 저장 키이므로 사용을 시작한 뒤 임의로 변경하지 않는다.
- 이벤트 데이터는 Yarn Node, 반복 여부, 선행 이벤트를 가진다.
- 영구적인 완료 상태는 이벤트 관리 시스템만 변경한다.
- Yarn 변수는 이벤트 내부의 임시 분기와 연출에 사용한다.
- Yarn은 Command를 통해 다른 게임 시스템에 행동을 요청한다.
- Yarn Function은 게임 상태를 조회하는 용도로 사용한다.

## 설계 의도
이벤트마다 전용 관리자와 완료 여부를 추가하면 이벤트가 늘어날 때마다 기존 코드와 저장 구조를 수정해야 한다.

이를 피하기 위해 이벤트의 내용은 Yarn에 두고, 실행 조건과 완료 상태는 공통 시스템에서 관리한다. 새 이벤트는 데이터 등록으로 추가하고, 새로운 기능이 필요할 때만 재사용 가능한 기능을 확장한다.
